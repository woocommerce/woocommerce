# Order fulfillments

The order fulfillments API allows you to create, view, update, and delete fulfillments for an order, along with their metadata (tracking numbers, shipment provider, and any custom data you want to attach).

:::info

These endpoints are only available when the **Order Fulfillments** feature is enabled (`woocommerce_feature_fulfillments_enabled` option). If the feature is disabled, these routes are not registered and requests to them will return a `404 rest_no_route` error.

:::

## Order fulfillment properties

| Attribute      | Type      | Description                                                                                                                       |
| -------------- | --------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `id`           | integer   | Unique identifier for the fulfillment. `READ-ONLY`                                                                 |
| `entity_type`  | string    | The type of entity this fulfillment belongs to. Currently always `WC_Order`. `READ-ONLY`                          |
| `entity_id`    | string    | The ID of the entity this fulfillment belongs to, i.e. the order ID. `READ-ONLY`                                   |
| `status`       | string    | Status of the fulfillment, e.g. `unfulfilled` or `fulfilled`. Custom statuses can also be used. Default is `unfulfilled`.           |
| `is_fulfilled` | boolean   | Whether the fulfillment is fulfilled. Default is `false`.                                                                          |
| `date_updated` | date-time | The date the fulfillment was last updated, as GMT, in ISO 8601 format (e.g. `2024-01-15T11:45:00Z`). `READ-ONLY`   |
| `date_deleted` | date-time | The date the fulfillment was deleted, as GMT, or `null` if it hasn't been deleted. `READ-ONLY`                     |
| `meta_data`    | array     | Meta data. See [Order fulfillment - Meta data properties](#order-fulfillment---meta-data-properties)                                |

The following parameters are also accepted when creating or updating a fulfillment, but are not part of the stored resource:

| Attribute         | Type    | Description                                                                                                                            |
| ----------------- | ------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `notify_customer` | boolean | Whether to notify the customer about this change. Default is `false`. `WRITE-ONLY`                                     |
| `customer_note`   | string  | An optional note from the merchant, included in the update notification email. Only used when updating a fulfillment. `WRITE-ONLY` |

:::note

When you create or update a fulfillment, only `status`, `is_fulfilled`, and `meta_data` from the JSON body are applied to the fulfillment. The order ID comes from the URL path. On update, the fulfillment ID also comes from the URL path. On create, the server assigns it. A top-level `id`, `entity_type`, or `entity_id` in the body is silently ignored, so a request body cannot change which order or fulfillment is written to. These three fields are still returned in responses. `notify_customer` and `customer_note` (update only) are request parameters that control notifications. They are not stored on the fulfillment.

:::

### Order fulfillment - Meta data properties

| Attribute | Type    | Description                                                                     |
| --------- | ------- | -------------------------------------------------------------------------------- |
| `id`      | integer | Meta ID. `0` for entries that haven't been saved yet. `READ-ONLY` |
| `key`     | string  | Meta key.                                                                       |
| `value`   | mixed   | Meta value. Can be a string, number, array, or object.                         |

The `_items` meta key is required and must be an array of objects describing which order line items are being fulfilled:

```json
[
	{
		"item_id": 456,
		"qty": 2
	}
]
```

| Field     | Type    | Description                                    |
| --------- | ------- | ---------------------------------------------- |
| `item_id` | integer | The order line item ID.                        |
| `qty`     | number  | Positive quantity of the item being fulfilled. |

Other common (optional) meta keys: `_tracking_number`, `_shipment_provider`, `_tracking_url`, and `_date_fulfilled` (stored as GMT and returned in ISO 8601 format, e.g. `2024-01-16T11:45:00Z`). Meta keys prefixed with an underscore are private and only shown to merchants and in customer emails; unprefixed keys are also shown to merchants and customers alongside the fulfillment.

## Create a fulfillment

On create, `meta_data` is itself a required parameter (it must contain at least the `_items` entry). Omitting the `meta_data` wrapper returns a `400` with the code `rest_missing_callback_param`.

```http
POST /wp-json/wc/v3/orders/<id>/fulfillments
```

<Tabs>
  <TabItem value="curl" label="cURL">

```shell
curl -X POST "https://example.com/wp-json/wc/v3/orders/723/fulfillments?notify_customer=true" \
	-u consumer_key:consumer_secret \
	-H "Content-Type: application/json" \
	-d '{
  "status": "fulfilled",
  "is_fulfilled": true,
  "meta_data": [
    {
      "key": "_items",
      "value": [
        { "item_id": 456, "qty": 2 }
      ]
    },
    {
      "key": "_tracking_number",
      "value": "1Z999AA1234567890"
    },
    {
      "key": "_shipment_provider",

}'
```

## Update a fulfillment

Any `meta_data` entries not included in the request are removed from the fulfillment, so send the full set of metadata you want the fulfillment to have. As a safeguard against accidental data loss, if the request's `meta_data` is non-empty but every entry is malformed (no valid key), the existing metadata is left untouched rather than cleared.

```http
PUT /wp-json/wc/v3/orders/<id>/fulfillments/<fulfillment_id>
```

## Update fulfillment metadata

Like updating a fulfillment, this replaces the full metadata set: any existing meta keys not present in the request body are removed.

The metadata must be wrapped in an object under the `meta_data` key. The endpoint requires the `meta_data` parameter, so sending a bare array returns a `400 rest_missing_callback_param` error. Because the request replaces the full set, keep `_items` in the payload. The metadata update and delete endpoints cannot remove `_items`; saving without it fails with "The fulfillment should contain at least one item."

| Parameter          | Type    | Description                      |
| ------------------ | ------- | --------------------------------- |

-   Missing `tracking_number`: WordPress rejects the request before the endpoint runs, because the parameter is registered as required. The response is a `400` with the code `rest_missing_callback_param`.

## Prepare a fulfillments import

Uploads a CSV of tracking data, reads its header row and opens an import session for the column-mapping step of the import wizard. Requires the `manage_woocommerce` capability. Each user has one import session at a time: a successful call replaces the caller's previous session and removes its staged file, while a rejected upload (a `400` or `413` response) leaves the previous session untouched.

The request body is `multipart/form-data`. The official client libraries do not send multipart requests, so the example uses cURL.

```http
POST /wp-json/wc/v3/fulfillments/import/prepare
```

<Tabs>
  <TabItem value="curl" label="cURL">

```shell
curl -X POST "https://example.com/wp-json/wc/v3/fulfillments/import/prepare" \
	-u consumer_key:consumer_secret \
	-F "file=@shipments.csv;type=text/csv" \
	-F "delimiter=,"
```

  </TabItem>
  <TabItem value="response" label="JSON Response">

```json
{
	"token": "6b4c90a944064f5ba32938f140d453d5",
	"headers": ["order_id", "tracking_number", "shipment_provider", "tracking_url"],
	"sample": ["101", "1Z999AA10123456784", "ups", "https://www.ups.com/track?tracknum=1Z999AA10123456784"],
	"total": 1,
	"detected_mapping": {
		"0": "order_number",
		"1": "tracking_number",
		"2": "shipment_provider",
		"3": "tracking_url"
	},
	"delimiter": ","
}
```

  </TabItem>
</Tabs>

#### Available parameters

| Parameter         | Type    | Description                                                                                                                    |
| ----------------- | ------- | ------------------------------------------------------------------------------------------------------------------------------ |
| `file`            | file    | Required. The CSV file to import, up to the site's upload size limit and at most 5,000 data rows. A `.txt` file is accepted only when WordPress identifies its content as plain text; comma-separated content must use the `.csv` extension. |
| `delimiter`       | string  | Single ASCII character used as the column delimiter, or `tab`. Defaults to `,`.                                                 |
| `notify_customer` | boolean | Initial value for the import run: whether customers are notified about imported fulfillments. Stored on the session. Defaults to `false`. |
| `update_existing` | boolean | Initial value for the import run: whether a fulfillment with the same tracking number is updated instead of skipped. Stored on the session. Defaults to `true`. |

#### Response properties

| Property           | Type    | Description                                                                                            |
| ------------------ | ------- | ------------------------------------------------------------------------------------------------------ |
| `token`            | string  | Import session token to pass to the next step of the import.                                           |
| `headers`          | array   | Header row of the staged CSV. The first non-blank record is the header.                               |
| `sample`           | array   | First non-blank data row, for the mapping preview. Cells are trimmed and padded to the header length. |
| `total`            | integer | Number of non-blank data rows.                                                                         |
| `detected_mapping` | object  | Auto-detected canonical column for each CSV column index. Columns that were not detected are omitted.  |
| `delimiter`        | string  | Delimiter used to read the file.                                                                       |

Error codes specific to this endpoint:

-   `woocommerce_fulfillments_import_no_file` (`400`) - No file was uploaded.
-   `woocommerce_fulfillments_import_file_too_large` (`413`) - The file exceeds the upload size limit, including a file PHP itself refused for its size, or the site has no upload space left (multisite quota).
-   `woocommerce_fulfillments_import_upload_failed` (`400` or `500`) - The file could not be staged, is not a CSV, or was stored outside the import directory.
-   `woocommerce_fulfillments_csv_parse_error` (`400`) - The file is empty, unreadable, not valid UTF-8, saved as UTF-16 or with CR-only line endings, or has no data rows. The error `data.reason` carries the importer's code.
-   `woocommerce_fulfillments_import_too_many_rows` (`413`) - The file has more than 5,000 data rows.
-   `woocommerce_fulfillments_import_chunk_in_progress` (`409`) - Another request of the caller's import is being processed: a chunk, or another upload. The upload is dropped and the current session is kept; send the file again in a moment.
-   `woocommerce_fulfillments_import_lock_failed` (`500`) - The import could not be locked because of a database error. The upload is dropped and the current session is kept.
-   `woocommerce_fulfillments_import_session_failed` (`500`) - The import session could not be stored, or the cleanup of its staged file could not be scheduled. The staged file is removed. The caller's previous session was replaced before this point and is gone as well.
-   `rest_invalid_param` (`400`) - The `delimiter` is not a single ASCII character or `tab`, or `notify_customer` or `update_existing` is not a boolean.
-   `woocommerce_rest_cannot_create` (`401` or `403`) - The request is not authenticated or the user lacks `manage_woocommerce`.

## Run a fulfillments import

Imports the next chunk of data rows from the file a prepare call staged, and records the progress on the import session. Call it in a loop: start with `offset` `0`, then send the `processed` value of each response as the next `offset`, until `done` is `true`. Requires the `manage_woocommerce` capability, and the token must belong to the calling user.

Each row creates a fulfilled fulfillment on its order, or updates the order's fulfillment that has the same tracking number. A row that cannot be imported fails on its own and the rest of the chunk still imports. The `mapping` and `options` of the first chunk are stored on the session; later chunks import under them whatever they send.

```http
POST /wp-json/wc/v3/fulfillments/import/run
```

<Tabs>
  <TabItem value="curl" label="cURL">

```shell
curl -X POST "https://example.com/wp-json/wc/v3/fulfillments/import/run" \
	-u consumer_key:consumer_secret \
	-H "Content-Type: application/json" \
	-d '{
	"token": "6b4c90a944064f5ba32938f140d453d5",
	"offset": 0,
	"mapping": { "0": "order_number", "1": "tracking_number", "2": "shipment_provider", "3": "tracking_url" },
	"options": { "notify_customer": false, "update_existing": true }
}'
```

  </TabItem>
  <TabItem value="response" label="JSON Response">

```json
{
	"processed": 2,
	"total": 2,
	"done": true,
	"counts": { "created": 1, "updated": 0, "skipped": 0, "failed": 1, "notified": 0 },
	"rows": [
		{
			"row": 2,
			"order_number": "101",
			"status": "created",
			"message": "Fulfillment created.",
			"order_id": 101,
			"fulfillment_id": 12,
			"notified": false,
			"order_edit_url": "https://example.com/wp-admin/admin.php?page=wc-orders&action=edit&id=101"
		},
		{
			"row": 3,
			"order_number": "999",
			"status": "failed",
			"message": "Order not found for order number \"999\".",
			"code": "order_not_found"
		}
	],
	"summary": { "created": 1, "updated": 0, "skipped": 0, "failed": 1, "notified": 0, "rows": [] }
}
```

  </TabItem>
</Tabs>

#### Available parameters

| Parameter | Type    | Description                                                                                                                                                                                              |
| --------- | ------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `token`   | string  | Required. The `token` a prepare call returned.                                                                                                                                                            |
| `offset`  | integer | Number of data rows processed so far: `0` for the first chunk, then the `processed` value of the previous response. Defaults to `0`.                                                                      |
| `limit`   | integer | Most data rows to import in this request, from 1 to 1000. Defaults to, and is capped by, the store's chunk size: 200 rows, or 25 while customers are notified.                                            |
| `mapping` | object  | Required. Canonical column (`order_number`, `tracking_number`, `shipment_provider`, `tracking_url` or `items`) for each CSV column index. The first three are required, and a column can be used once.   |
| `options` | object  | `notify_customer` and `update_existing` booleans. An option left out keeps the value sent to the prepare call.                                                                                            |

#### Response properties

| Property    | Type    | Description                                                                                                                                              |
| ----------- | ------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `processed` | integer | Data rows processed so far. Send it as the `offset` of the next request.                                                                                 |
| `total`     | integer | Number of non-blank data rows in the file.                                                                                                               |
| `done`      | boolean | Whether every data row has been processed.                                                                                                               |
| `counts`    | object  | Results of all chunks so far: `created`, `updated`, `skipped`, `failed`, and `notified`, the rows whose customer notification action ran.                |
| `rows`      | array   | Result of each row in this chunk.                                                                                                                        |
| `summary`   | object  | Present once `done` is `true`: the final counts and an empty `rows` list.                                                                                |

Each entry of `rows` has `row` (the record number in the file, counting the header and blank lines), `order_number` (the cell from the file), `status` (`created`, `updated`, `skipped` or `failed`) and `message`. A failed row adds `code`. `order_id` and `order_edit_url` are set once the order is found, `fulfillment_id` when the row matched or saved a fulfillment, and `notified` on created and updated rows. `message` is plain text that can quote values from the file, so escape it before output.

#### Sending a chunk again

A response can be lost after the server imported the chunk. Sending the same `offset` again is safe: the offset of the last recorded chunk is answered with the stored result of that chunk, and nothing is imported or emailed twice. This also works for the last chunk, because a finished session is kept for an hour, or until the user's next prepare call. Its staged file is removed when the import finishes.

Only one request per user runs at a time. A request that arrives while another one is importing gets `woocommerce_fulfillments_import_chunk_in_progress`; it imported nothing and can be sent again. A prepare call made during that time gets the same error. The lock of a request that never ended (PHP was killed) expires after five minutes. A chunk that is still running at that point can lose its lock to another request: it then answers `woocommerce_fulfillments_import_lock_lost` and its rows may be imported by both.

Error codes specific to this endpoint:

-   `woocommerce_fulfillments_import_token_invalid` (`400`) - The session does not exist, has expired, or belongs to another user.
-   `woocommerce_fulfillments_import_mapping_invalid` (`400`) - The mapping lacks a required column, names a column the file does not have, or uses a canonical column twice.
-   `woocommerce_fulfillments_import_chunk_in_progress` (`409`) - Another request of this user is importing a chunk. Nothing was imported.
-   `woocommerce_fulfillments_import_offset_mismatch` (`409`) - The `offset` is neither the recorded progress nor the offset of the last recorded chunk, or the import has already finished and the `offset` is not that of its last chunk. Nothing was imported.
-   `woocommerce_fulfillments_import_file_changed` (`409`) - The staged file was changed or removed after the prepare call. The session is deleted.
-   `woocommerce_fulfillments_import_chunk_failed` (`500`) - The staged file could not be read. Nothing was imported and the session is kept. The error `data.reason` carries the importer's code.
-   `woocommerce_fulfillments_import_progress_failed` (`500`) - The settings or the progress of the chunk could not be saved. When it was the progress, the rows are already imported: the same `offset` imports them again and reports them as skipped or updated.
-   `woocommerce_fulfillments_import_lock_failed` (`500`) - The import could not be locked because of a database error. Nothing was imported.
-   `woocommerce_fulfillments_import_lock_lost` (`500`) - The chunk ran longer than its lock and another request took over. Its rows are imported but not recorded by this request; send the same `offset` again.
-   `rest_missing_callback_param` (`400`) - `token` or `mapping` is missing.
-   `rest_invalid_param` (`400`) - An argument is outside the limits above.
-   `woocommerce_rest_cannot_create` (`401` or `403`) - The request is not authenticated or the user lacks `manage_woocommerce`.

## Error responses

Errors follow the standard WooCommerce REST API error shape:

```json
{
	"code": "error_code",
	"message": "Error message description",
	"data": {
		"status": 400
	}
}
```

Common error codes for the fulfillments endpoints:

-   `woocommerce_rest_order_invalid_id` - The order ID does not exist.
-   `woocommerce_rest_order_id_missing` - The order ID is required but was not supplied.
-   `rest_missing_callback_param` - A required parameter was omitted, for example a missing `tracking_number`.
-   `woocommerce_rest_tracking_number_missing` - The `tracking_number` parameter was supplied but is empty.
-   Standard authentication/authorization errors. Creating, updating, and deleting fulfillments requires the `manage_woocommerce` capability. A customer who owns the order (but lacks `manage_woocommerce`) has read-only access: they can list and retrieve the order's fulfillments and metadata, but write requests return an authorization error.
