# WooCommerce GraphQL API - Supporting Code Specification (Stage 2)

This document specifies all supporting code for the GraphQL API infrastructure: the build script, the autogenerated code it produces, the fixed infrastructure code (GraphQL endpoint handler and initialization), and the templates used during code generation.

All references to the Code API specification refer to `stage1-code-api-spec-v2.md`.

---

## 1. Overview

The supporting code lives entirely in `src/Internal/Api/` and breaks down into four categories:

| Category | Location | In package? | Maintained by |
|---|---|---|---|
| Build script & helpers | `Scripts/` | No (excluded from build) | Developer |
| Code generation templates | `Templates/` | No (excluded from build) | Developer |
| Autogenerated GraphQL code | `Autogenerated/` | Yes (committed to source) | Build script only |
| Fixed infrastructure | `GraphQLController.php`, `Main.php` | Yes | Developer |

Namespace root: `Automattic\WooCommerce\Internal\Api`

## 2. Build Script (`Scripts/ApiBuilder.php`)

### 2.1. Entry point

The build script is invoked via:

```sh
pnpm run build:api
```

This runs a PHP CLI script that instantiates and calls `ApiBuilder`:

```php
// src/Internal/Api/Scripts/build-api.php

require_once __DIR__ . '/../../../../vendor/autoload.php';

use Automattic\WooCommerce\Internal\Api\Scripts\ApiBuilder;

$builder = new ApiBuilder();
$builder->build();
```

### 2.2. Build process overview

```
ApiBuilder::build()
├── 1. Discover all PHP classes in src/Api/
├── 2. Classify each class by directory (Queries, Mutations, Types, etc.)
├── 3. Resolve attributes and type information via reflection
├── 4. Validate all rules (Stage 1 spec compliance)
├── 5. Wipe Autogenerated/ directory
├── 6. Generate GraphQL type classes (GraphQLTypes/)
├── 7. Generate query resolver classes (GraphQLQueries/)
├── 8. Generate mutation resolver classes (GraphQLMutations/)
├── 9. Generate RootQueryType.php and RootMutationType.php
├── 10. Write api_generation_date.txt
└── 11. Regenerate PHP autoloader
```

### 2.3. Discovery and classification

The builder scans `src/Api/` recursively, loading all `.php` files. Each class/enum/trait is classified based on its namespace (which corresponds to its directory):

| Namespace suffix | Entity type |
|---|---|
| `Api\Queries\**` | Query command class |
| `Api\Mutations\**` | Mutation command class |
| `Api\Types\**` | Output type (DTO) |
| `Api\InputTypes\**` | Input type (DTO) |
| `Api\Enums\**` | Enum type |
| `Api\Interfaces\**` | Interface (trait) |
| `Api\Scalars\**` | Custom scalar |
| `Api\Pagination\**` | Built-in pagination types (skipped — handled specially) |
| `Api\Attributes\**` | Attribute definitions (skipped — not generated) |
| `Api\ApiException` | Exception class (skipped) |

Classes marked with `#[Ignore]` are excluded from generation but still tracked for validation.

### 2.4. Reflection and metadata extraction

For each discovered class, the builder uses PHP's `ReflectionClass` (and related reflection APIs) to extract:

- **Class-level attributes**: `#[Description]`, `#[RequiredCapability]`, `#[PublicAccess]`, `#[Name]`, `#[Ignore]`, `#[Deprecated]`
- **Property attributes**: `#[Description]`, `#[ArrayOf]`, `#[ScalarType]`, `#[ConnectionOf]`, `#[Parameter]`, `#[ParameterDescription]`, `#[Name]`, `#[Ignore]`, `#[Deprecated]`
- **Method attributes** (for `execute`): `#[ConnectionOf]`, `#[Description]` on parameters
- **Type information**: property types, method parameter types, return types
- **Trait usage**: which traits from `Api\Interfaces\` are used (to determine GraphQL interface implementation)
- **Inheritance chain**: parent classes, for capability inheritance resolution

### 2.5. Validation rules

The build script validates all rules from Stage 1 and aborts with clear error messages on failure:

1. **Required capability resolution**: Every query/mutation class must have `#[RequiredCapability]` (directly or inherited) or `#[PublicAccess]`. Missing = error.
2. **Capability + PublicAccess mutual exclusion**: A class cannot have both (including via inheritance).
3. **Type constraints**: All property types, parameter types, and return types use only allowed types for their context (as specified in Stage 1, sections 4–7).
4. **ArrayOf required for arrays**: Any `array`-typed property, parameter, or return type must have an `#[ArrayOf]` attribute.
5. **ConnectionOf required for Connection returns**: Any method returning `Connection` or property typed as `Connection` must have `#[ConnectionOf]`.
6. **Ignored references**: A non-ignored entity must not reference an ignored entity (error).
7. **Parameter/ParameterDescription conflict**: Both `description` in `#[Parameter]` and a `#[ParameterDescription]` for the same parameter name = error.
8. **GraphQL name uniqueness**: No two entities of the same kind may resolve to the same GraphQL name.
9. **Execute method**: Query and mutation classes must have exactly one public method named `execute`.
10. **Enum backing**: All enums must be backed (`string` or `int`).
11. **Scalar class structure**: Custom scalar classes must have static `serialize` and `parse` methods.

### 2.6. Generated file naming

Generated classes use clean names without redundant suffixes. The sub-directory (and corresponding sub-namespace) conveys the entity kind.

| Entity | Generated file | Generated class (short name) |
|---|---|---|
| Output type `Order` | `GraphQLTypes/Output/Order.php` | `Order` |
| Input type `CreateOrderInput` | `GraphQLTypes/Input/CreateOrder.php` | `CreateOrder` |
| Enum `OrderStatus` | `GraphQLTypes/Enums/OrderStatus.php` | `OrderStatus` |
| Interface trait `HasId` | `GraphQLTypes/Interfaces/HasId.php` | `HasId` |
| Custom scalar `DateTime` | `GraphQLTypes/Scalars/DateTime.php` | `DateTime` |
| Connection for `Order` | `GraphQLTypes/Pagination/OrderConnection.php` | `OrderConnection` |
| Edge for `Order` | `GraphQLTypes/Pagination/OrderEdge.php` | `OrderEdge` |
| PageInfo (shared) | `GraphQLTypes/Pagination/PageInfo.php` | `PageInfo` |
| Query `GetOrder` | `GraphQLQueries/GetOrder.php` | `GetOrder` |
| Mutation `CreateOrder` | `GraphQLMutations/CreateOrder.php` | `CreateOrder` |

**Input type name stripping**: Input type class names that end with "Input" have that suffix stripped in the generated class name (e.g., `CreateOrderInput` → `CreateOrder` in `GraphQLTypes/Input/`), since the `Input/` directory already conveys the kind. Input type names that don't end with "Input" are kept as-is.

**Namespace structure**:

| Sub-directory | Namespace |
|---|---|
| `GraphQLTypes/Output/` | `Automattic\WooCommerce\Internal\Api\Autogenerated\GraphQLTypes\Output` |
| `GraphQLTypes/Input/` | `Automattic\WooCommerce\Internal\Api\Autogenerated\GraphQLTypes\Input` |
| `GraphQLTypes/Enums/` | `Automattic\WooCommerce\Internal\Api\Autogenerated\GraphQLTypes\Enums` |
| `GraphQLTypes/Interfaces/` | `Automattic\WooCommerce\Internal\Api\Autogenerated\GraphQLTypes\Interfaces` |
| `GraphQLTypes/Scalars/` | `Automattic\WooCommerce\Internal\Api\Autogenerated\GraphQLTypes\Scalars` |
| `GraphQLTypes/Pagination/` | `Automattic\WooCommerce\Internal\Api\Autogenerated\GraphQLTypes\Pagination` |
| `GraphQLQueries/` | `Automattic\WooCommerce\Internal\Api\Autogenerated\GraphQLQueries` |
| `GraphQLMutations/` | `Automattic\WooCommerce\Internal\Api\Autogenerated\GraphQLMutations` |

**Cross-namespace aliasing convention**: When generated code references a class whose short name collides with another import, aliases are used. The convention is:

- Code API class imported into a resolver of the same name: `use ...Api\Queries\GetOrder as GetOrderCommand;`
- Generated type imported from a different sub-namespace: `use ...GraphQLTypes\Enums\OrderStatus as OrderStatusType;`

For nested namespaces in the code API (e.g. `Api\Types\Orders\Order`), the directory structure in `Autogenerated/` is flattened (the class name alone determines the file name). The build script validates that there are no name collisions.

## 3. Autogenerated Code: GraphQL Type Classes

Each type class in `Autogenerated/GraphQLTypes/` creates and caches a single `webonyx/graphql-php` type instance.

### 3.1. Output type (ObjectType)

```php
// Autogenerated/GraphQLTypes/Output/Order.php

namespace Automattic\WooCommerce\Internal\Api\Autogenerated\GraphQLTypes\Output;

use Automattic\WooCommerce\Internal\Api\Autogenerated\GraphQLTypes\Enums\OrderStatus as OrderStatusType;
use Automattic\WooCommerce\Internal\Api\Autogenerated\GraphQLTypes\Interfaces\HasId as HasIdType;
use Automattic\WooCommerce\Internal\Api\Autogenerated\GraphQLTypes\Scalars\DateTime as DateTimeType;
use GraphQL\Type\Definition\ObjectType;
use GraphQL\Type\Definition\Type;

class Order {
    private static ?ObjectType $instance = null;

    public static function get(): ObjectType {
        if (self::$instance === null) {
            self::$instance = new ObjectType([
                'name' => 'Order',
                'description' => 'Represents a WooCommerce order.',
                'interfaces' => fn() => [
                    HasIdType::get(),
                ],
                'fields' => fn() => [
                    'id' => [
                        'type' => Type::nonNull(Type::int()),
                        'description' => 'The unique identifier.',
                    ],
                    'total_amount' => [
                        'type' => Type::nonNull(Type::float()),
                        'description' => 'The total amount of the order.',
                        'args' => [
                            'decimals' => [
                                'type' => Type::int(),
                                'defaultValue' => 2,
                                'description' => 'Decimal places to round to.',
                            ],
                        ],
                    ],
                    'date_created' => [
                        'type' => Type::nonNull(DateTimeType::get()),
                        'description' => 'The date the order was created, in ISO 8601 format.',
                    ],
                    'status' => [
                        'type' => Type::nonNull(OrderStatusType::get()),
                        'description' => 'The current status of the order.',
                    ],
                    'customer' => [
                        'type' => Customer::get(),
                        'description' => 'The customer who placed the order.',
                    ],
                    'applied_coupons' => [
                        'type' => Type::nonNull(Type::listOf(Type::nonNull(
                            AppliedCoupon::get()
                        ))),
                        'description' => 'Coupons applied to this order.',
                        'args' => [
                            'page' => [
                                'type' => Type::int(),
                                'defaultValue' => 1,
                                'description' => 'Page number.',
                            ],
                            'per_page' => [
                                'type' => Type::int(),
                                'defaultValue' => 10,
                                'description' => 'Results per page.',
                            ],
                        ],
                    ],
                ],
            ]);
        }
        return self::$instance;
    }
}
```

**Key patterns:**

- The `interfaces` and `fields` keys use **lazy closures** (`fn() =>`) to avoid circular reference issues (type A references type B which references type A).
- **Non-nullable properties** (no `?` in PHP type) produce `Type::nonNull(...)`. Nullable properties produce the bare type.
- **Array properties** with `#[ArrayOf]` produce `Type::listOf(Type::nonNull(...))` (items are non-null by default). If the array itself is nullable, the outer `nonNull` is omitted.
- **Field arguments** from `#[Parameter]` attributes become `args` entries on the field definition.
- **Trait properties** are merged into the owning class's field list (they are not resolved separately).
- **`#[Deprecated]`** properties add a `'deprecationReason'` key.
- **Same sub-namespace** references (e.g. `Customer::get()`, `AppliedCoupon::get()` from within `Output/`) need no aliasing. **Cross sub-namespace** references use aliases (e.g. `OrderStatusType`, `DateTimeType`, `HasIdType`).

### 3.2. Input type (InputObjectType)

```php
// Autogenerated/GraphQLTypes/Input/CreateOrder.php

namespace Automattic\WooCommerce\Internal\Api\Autogenerated\GraphQLTypes\Input;

use Automattic\WooCommerce\Internal\Api\Autogenerated\GraphQLTypes\Enums\OrderStatus as OrderStatusType;
use GraphQL\Type\Definition\InputObjectType;
use GraphQL\Type\Definition\Type;

class CreateOrder {
    private static ?InputObjectType $instance = null;

    public static function get(): InputObjectType {
        if (self::$instance === null) {
            self::$instance = new InputObjectType([
                'name' => 'CreateOrderInput',
                'description' => 'Data required to create a new order.',
                'fields' => fn() => [
                    'status' => [
                        'type' => Type::nonNull(OrderStatusType::get()),
                        'description' => 'The initial status of the order.',
                    ],
                    'customer_id' => [
                        'type' => Type::nonNull(Type::int()),
                        'description' => 'The customer ID.',
                    ],
                    'billing' => [
                        'type' => Type::nonNull(Address::get()),
                        'description' => 'Billing address.',
                    ],
                    'tags' => [
                        'type' => Type::nonNull(Type::listOf(Type::nonNull(Type::string()))),
                        'description' => 'Tags for the order.',
                    ],
                ],
            ]);
        }
        return self::$instance;
    }
}
```

**Key patterns:**

- The PHP class name strips the "Input" suffix (`CreateOrder`), but the GraphQL name retains it (`CreateOrderInput`) for schema clarity.
- Properties with PHP default values produce fields without `Type::nonNull(...)` (they're optional in GraphQL).
- Nullable properties are also optional.
- Input types never have `args` (field arguments are only for output types).
- Input types cannot reference output types (only other input types, enums, scalars, primitives).

```php
                        'description' => 'Order has been cancelled.',
                    ],
```

**Key patterns:**

- The code API enum is imported with an `Enum` suffix alias (`OrderStatusEnum`) to avoid collision with the generated class name.

- Case names are converted from PascalCase to SCREAMING_SNAKE_CASE, unless overridden by `#[Name]`.
- `#[Deprecated]` cases include `'deprecationReason'`.

### 3.4. Interface type (InterfaceType)

```php
// Autogenerated/GraphQLTypes/Interfaces/HasId.php

namespace Automattic\WooCommerce\Internal\Api\Autogenerated\GraphQLTypes\Interfaces;

use Automattic\WooCommerce\Internal\Api\Autogenerated\GraphQLTypes\Output\Order as OrderType;
use Automattic\WooCommerce\Internal\Api\Autogenerated\GraphQLTypes\Output\Webhook as WebhookType;
use GraphQL\Type\Definition\InterfaceType;
use GraphQL\Type\Definition\ObjectType;
use GraphQL\Type\Definition\Type;

class HasId {
    private static ?InterfaceType $instance = null;

    public static function get(): InterfaceType {
        if (self::$instance === null) {
            self::$instance = new InterfaceType([
                'name' => 'HasId',
                'description' => 'An entity with a unique identifier.',
                'fields' => fn() => [
                    'id' => [
                        'type' => Type::nonNull(Type::int()),
                        'description' => 'The unique identifier.',
                    ],
                ],
                'resolveType' => fn($value) => self::resolveType($value),
            ]);
        }
        return self::$instance;
    }

    /**
     * Resolves the concrete GraphQL type for a PHP object implementing this interface.
     */
    private static function resolveType(object $value): ObjectType {
        // Map from PHP class to GraphQL type. The build script generates
        // this mapping from all output types that `use` the HasId trait.
        $type_map = [
            \Automattic\WooCommerce\Api\Types\Order::class => OrderType::class,
            \Automattic\WooCommerce\Api\Types\Webhook::class => WebhookType::class,
            // ... all types using HasId
        ];

        $php_class = get_class($value);
        if (isset($type_map[$php_class])) {
            return $type_map[$php_class]::get();
        }

        throw new \RuntimeException("Cannot resolve GraphQL type for " . $php_class);
    }
}
```

**Key patterns:**

- `resolveType` is required by `webonyx/graphql-php` to determine which concrete ObjectType a returned object belongs to.
- The type map is generated at build time from all output types that `use` the trait.
- Output types are imported with a `Type` suffix alias to avoid collision with the code API classes.

## 4. Autogenerated Code: Query Resolvers

Each query command class gets a generated resolver in `Autogenerated/GraphQLQueries/`.

### 4.1. Resolver structure

```php
// Autogenerated/GraphQLQueries/GetOrder.php

namespace Automattic\WooCommerce\Internal\Api\Autogenerated\GraphQLQueries;

use Automattic\WooCommerce\Api\Queries\GetOrder as GetOrderCommand;
use Automattic\WooCommerce\Internal\Api\Autogenerated\FieldArgumentExtractor;
use Automattic\WooCommerce\Internal\Api\Autogenerated\GraphQLTypes\Output\Order as OrderType;
use GraphQL\Type\Definition\ResolveInfo;
use GraphQL\Type\Definition\Type;

class GetOrder {
    /**
     * Returns the field definition for the root Query type.
     */
    public static function getFieldDefinition(): array {
        return [
            'type' => OrderType::get(),
            'description' => 'Retrieve an order by ID.',
            'args' => [
                'id' => [
                    'type' => Type::nonNull(Type::int()),
                    'description' => 'The order ID.',
                ],
            ],
            'resolve' => [self::class, 'resolve'],
        ];
    }

    /**
     * Resolves the query.
     */
    public static function resolve(mixed $root, array $args, mixed $context, ResolveInfo $info): mixed {
        // 1. Capability check
        self::checkCapabilities();

        // 2. Resolve the command from DI container
        $command = wc_get_container()->get(GetOrderCommand::class);

        // 3. Extract infrastructure parameters from resolve info
        $execute_args = [];
        $execute_args['id'] = $args['id'];
        $execute_args['_field_arguments'] = self::extractFieldArguments($info);

        // 4. Invoke execute
        $result = $command->execute(...$execute_args);

        // 5. Convert enum values for GraphQL transport
        return self::mapResult($result);
    }

    private static function checkCapabilities(): void {
        $required = ['read_shop_orders'];
        foreach ($required as $cap) {
            if (!current_user_can($cap)) {
                throw new \GraphQL\Error\Error(
                    'You do not have permission to perform this action.',
                    extensions: ['code' => 'UNAUTHORIZED']
                );
            }
        }
    }

    /**
     * Extracts field arguments from the GraphQL ResolveInfo into the
     * $_field_arguments format expected by the Code API.
     */
    private static function extractFieldArguments(ResolveInfo $info): ?array {
        $field_nodes = $info->fieldNodes;
        if (empty($field_nodes)) {
            return null;
        }

        return FieldArgumentExtractor::extract(
            $field_nodes[0]->selectionSet,
            $info->variableValues
        );
    }

    private static function mapResult(mixed $result): mixed {
        // Identity for now — webonyx/graphql-php handles enum serialization
        // via the EnumType value mapping. DTO properties are resolved by
        // the default field resolver (public property access).
        return $result;
    }
}
```

### 4.2. Resolver pipeline

Each generated resolver follows the same pipeline:

```
resolve($root, $args, $context, $info)
│
├── 1. checkCapabilities()
│   └── Checks all accumulated #[RequiredCapability] attributes.
│       Throws GraphQL\Error\Error with UNAUTHORIZED code on failure.
│       Skipped if #[PublicAccess] is declared.
│
├── 2. Resolve command instance
│   └── wc_get_container()->get(CommandClass::class)
│       The container calls init() for DI if the class has one.
│
├── 3. Build execute() arguments
│   ├── Map $args to execute() parameter names
│   ├── Convert GraphQL input objects → PHP InputType DTOs (recursive)
│   ├── Convert GraphQL enum values → PHP enum instances
│   ├── If execute() has $_requested_fields: extract from $info
│   ├── If execute() has $_field_arguments: extract from $info
│   └── Arguments with defaults are omitted if not provided by client
│
├── 4. Call $command->execute(...$execute_args)
│
└── 5. Return result
    └── The result is a DTO or null. webonyx/graphql-php resolves
        individual fields via the default field resolver (property access).
```

### 4.3. Input type argument conversion

When an `execute` parameter is an input type, the generated resolver converts the raw associative array from GraphQL into a PHP DTO instance. Since the build script knows every property and its type at generation time, the conversion is hardcoded — no reflection is used at runtime.

Each generated resolver has a dedicated static method per input type it handles:

```php
// In GetOrder (or any resolver that accepts CreateOrderInput)

use Automattic\WooCommerce\Api\InputTypes\CreateOrderInput;
use Automattic\WooCommerce\Api\InputTypes\AddressInput;
use Automattic\WooCommerce\Api\Enums\OrderStatus as OrderStatusEnum;

private static function convertCreateOrderInput(array $data): CreateOrderInput {
    $input = new CreateOrderInput();

    if (array_key_exists('status', $data)) {
        $input->status = OrderStatusEnum::from($data['status']);
    }
    if (array_key_exists('customer_id', $data)) {
        $input->customer_id = $data['customer_id'];
    }
    if (array_key_exists('billing', $data)) {
        $input->billing = self::convertAddressInput($data['billing']);
    }
    if (array_key_exists('tags', $data)) {
        $input->tags = $data['tags'];
    }

    return $input;
}

private static function convertAddressInput(array $data): AddressInput {
    $input = new AddressInput();

    if (array_key_exists('line_1', $data)) {
        $input->line_1 = $data['line_1'];
    }
    if (array_key_exists('city', $data)) {
        $input->city = $data['city'];
    }
    // ... one assignment per property, generated at build time

    return $input;
}
```

The build script generates one `convert*` method for each input type referenced by the resolver. The conversion logic for each property is determined at build time based on its type:

| Property type | Generated conversion |
|---|---|
| Primitive (`int`, `string`, etc.) | Direct assignment |
| Enum (`OrderStatus`) | `EnumClass::from($data['name'])` |
| Nested input type (`AddressInput`) | `self::convertAddressInput($data['name'])` |
| Array of primitives | Direct assignment |
| Array of enums | `array_map(fn($v) => EnumClass::from($v), $data['name'])` |
| Array of input types | `array_map(fn($v) => self::convertNestedInput($v), $data['name'])` |

### 4.4. Extracting `$_requested_fields`

When the `execute` method has a `$_requested_fields` parameter, the resolver extracts it from `ResolveInfo`:

```php
private static function extractRequestedFields(ResolveInfo $info): array {
    return self::selectionSetToArray($info->fieldNodes[0]->selectionSet);
}

private static function selectionSetToArray(?\GraphQL\Language\AST\SelectionSetNode $set): ?array {
    if ($set === null) {
        return null;
    }

    $fields = [];
    foreach ($set->selections as $selection) {
        if ($selection instanceof \GraphQL\Language\AST\FieldNode) {
            $name = $selection->name->value;
            if ($selection->selectionSet !== null) {
                $fields[$name] = self::selectionSetToArray($selection->selectionSet);
            } else {
                $fields[$name] = null;
            }
        }
        // Inline fragments and fragment spreads are resolved similarly.
    }
    return $fields;
}
```

### 4.5. Extracting `$_field_arguments`

The `FieldArgumentExtractor` helper (generated in `Autogenerated/`) walks the selection set and collects field arguments in the `$_field_arguments` format:

```php
// Autogenerated/FieldArgumentExtractor.php

namespace Automattic\WooCommerce\Internal\Api\Autogenerated;

use GraphQL\Language\AST\SelectionSetNode;
use GraphQL\Language\AST\FieldNode;
use GraphQL\Language\AST\ArgumentNode;

class FieldArgumentExtractor {
    /**
     * Extracts field arguments from a selection set into the $_field_arguments format.
     *
     * @param SelectionSetNode|null $selectionSet The selection set to process.
     * @param array $variableValues Variable values from the query.
     * @return array|null The field arguments array, or null if no field has arguments.
     */
    public static function extract(?SelectionSetNode $selectionSet, array $variableValues): ?array {
        if ($selectionSet === null) {
            return null;
        }

        $result = [];

        foreach ($selectionSet->selections as $selection) {
            if (!($selection instanceof FieldNode)) {
                continue;
            }

            $field_name = $selection->name->value;
            $entry = [];

            // Collect arguments for this field
            if (!empty($selection->arguments)) {
                foreach ($selection->arguments as $arg) {
                    $entry[$arg->name->value] = self::resolveArgumentValue(
                        $arg, $variableValues
                    );
                }
            }

            // Recurse into sub-selections (for nested object/array fields)
            if ($selection->selectionSet !== null) {
                $sub_args = self::extract($selection->selectionSet, $variableValues);
                if ($sub_args !== null) {
                    // If the field is an array/list type, nest under '_item'
                    // The resolver knows which fields are lists from build-time metadata
                    $entry['_item'] = $sub_args;
                }
            }

            if (!empty($entry)) {
                $result[$field_name] = $entry;
            }
        }

        return empty($result) ? null : $result;
    }

    private static function resolveArgumentValue(ArgumentNode $arg, array $variableValues): mixed {
        $value_node = $arg->value;

        if ($value_node instanceof \GraphQL\Language\AST\VariableNode) {
            return $variableValues[$value_node->name->value] ?? null;
        }

        // webonyx/graphql-php AST value nodes have a `value` property for scalars
        return \GraphQL\Utils\AST::valueFromAST($value_node, null, $variableValues);
    }
}
```

**Determining `_item` nesting**: The build script knows at generation time which fields are array/list types (from `#[ArrayOf]` and `#[ConnectionOf]`). It generates the `_item` key only for list-type fields. For non-list object fields, sub-field arguments are merged directly without the `_item` wrapper.

## 7. Fixed Infrastructure: `GraphQLController.php`

This is a **manually maintained** class that registers and handles the GraphQL HTTP endpoint.

```php
// src/Internal/Api/GraphQLController.php

namespace Automattic\WooCommerce\Internal\Api;

use Automattic\WooCommerce\Api\ApiException;
use Automattic\WooCommerce\Internal\Api\Autogenerated\RootQueryType;
use Automattic\WooCommerce\Internal\Api\Autogenerated\RootMutationType;
use GraphQL\GraphQL;
use GraphQL\Type\Schema;
use GraphQL\Error\DebugFlag;
use GraphQL\Error\FormattedError;

class GraphQLController {
    private ?Schema $schema = null;

    /**
     * Register the GraphQL REST route.
     */
    public function register(): void {
        register_rest_route('wc/v4', '/graphql', [
            'methods' => 'POST',
            'callback' => [$this, 'handle_request'],
            'permission_callback' => '__return_true', // Auth is handled per-query/mutation
        ]);
    }

    /**
     * Handle an incoming GraphQL request.
     */
    public function handle_request(\WP_REST_Request $request): \WP_REST_Response {
        // 1. PHP version check
        if (PHP_VERSION_ID < 80100) {
            return $this->php_version_error_response($request);
        }

        // 2. Parse request body
        $query = $request->get_param('query');
        $variables = $request->get_param('variables') ?? [];
        $operation_name = $request->get_param('operationName');

        if (empty($query)) {
            return new \WP_REST_Response([
                'errors' => [
                    ['message' => 'No query provided.', 'extensions' => ['code' => 'BAD_REQUEST']],
                ],
            ], 400);
        }

        // 3. Load schema
        $schema = $this->get_schema();

        // 4. Execute
        try {
            $result = GraphQL::executeQuery(
                schema: $schema,
                source: $query,
                variableValues: $variables,
                operationName: $operation_name,
            );

            $debug_flags = $this->get_debug_flags($request);
            $output = $result->toArray($debug_flags);
        } catch (\Throwable $e) {
            $output = [
                'errors' => [
                    $this->format_exception($e, $request),
                ],
            ];
        }

        // 5. Determine HTTP status code
        $status = 200;
        if (isset($output['errors']) && !isset($output['data'])) {
            $status = $this->get_error_status($output['errors']);
        }

        return new \WP_REST_Response($output, $status);
    }

    /**
     * Build and cache the GraphQL schema.
     */
    private function get_schema(): Schema {
        if ($this->schema === null) {
            $this->schema = new Schema([
                'query' => RootQueryType::get(),
                'mutation' => RootMutationType::get(),
            ]);
        }
        return $this->schema;
    }

    /**
     * Determine debug flags based on WP_DEBUG, user role, and query string.
     */
    private function get_debug_flags(\WP_REST_Request $request): int {
        if (!$this->is_debug_mode($request)) {
            return DebugFlag::NONE;
        }
        return DebugFlag::INCLUDE_DEBUG_MESSAGE | DebugFlag::INCLUDE_TRACE;
    }

    /**
     * Check if debug mode is active.
     *
     * Debug mode is active when either:
     * - WP_DEBUG is enabled AND the current user is an administrator.
     * - The current user is an administrator AND `_debug=1` is in the query string.
     */
    private function is_debug_mode(\WP_REST_Request $request): bool {
        if (!current_user_can('manage_options')) {
            return false;
        }

        if (defined('WP_DEBUG') && WP_DEBUG) {
            return true;
        }

        // phpcs:ignore WordPress.Security.NonceVerification
        return isset($_GET['_debug']) && $_GET['_debug'] === '1';
    }

    /**
     * Return a fixed error for PHP < 8.1.
     */
    private function php_version_error_response(\WP_REST_Request $request): \WP_REST_Response {
        $message = 'The GraphQL API is not available on this server.';

        if ($this->is_debug_mode($request)) {
            $message .= sprintf(
                ' Reason: PHP 8.1 or later is required. Current version: %s.',
                PHP_VERSION
            );
        }

        return new \WP_REST_Response([
            'errors' => [
                ['message' => $message],
            ],
        ], 500);
    }

    /**
     * Format a caught exception into a GraphQL error array.
     */
    private function format_exception(\Throwable $e, \WP_REST_Request $request): array {
        if ($e instanceof ApiException) {
            $error = [
                'message' => $e->getMessage(),
                'extensions' => array_merge(
                    ['code' => $e->getErrorCode()],
                    $e->getExtensions()
                ),
            ];
        } elseif ($e instanceof \InvalidArgumentException) {
            $error = [
                'message' => $e->getMessage(),
                'extensions' => ['code' => 'INVALID_ARGUMENT'],
            ];
        } else {
            $error = [
                'message' => 'An unexpected error occurred.',
                'extensions' => ['code' => 'INTERNAL_ERROR'],
            ];
        }

        if ($this->is_debug_mode($request)) {
            $error['extensions']['debug'] = [
                'message' => $e->getMessage(),
                'file' => $e->getFile(),
                'line' => $e->getLine(),
                'trace' => $e->getTraceAsString(),
            ];
        }

        return $error;
    }

    /**
     * Determine the HTTP status code from an array of GraphQL errors.
     */
    private function get_error_status(array $errors): int {
        foreach ($errors as $error) {
            $code = $error['extensions']['code'] ?? null;
            if ($code === 'UNAUTHORIZED') {
                return 401;
            }
        }
        return 500;
    }
}
```

### 7.1. Error handling pipeline

The error handling has two layers:

**Layer 1: Per-resolver errors** (handled by `webonyx/graphql-php`):
- `ApiException` thrown in `execute()` → caught by the library and formatted per GraphQL spec. The generated resolver wraps the `execute` call to convert `ApiException` into `\GraphQL\Error\ClientAware` errors.
- `\InvalidArgumentException` → similarly caught and formatted.
- Other exceptions → generic "unexpected error" message, with full details in debug mode.

**Layer 2: Top-level errors** (handled by `GraphQLController`):
- Schema loading failures, parse errors, validation errors → caught in the try-catch in `handle_request`.

### 7.2. ClientAware error wrapping in resolvers

The generated resolvers wrap `execute()` calls to convert Code API exceptions into `webonyx/graphql-php`-compatible errors:

```php
// In each generated resolver's resolve() method:

try {
    $result = $command->execute(...$execute_args);
} catch (ApiException $e) {
    throw new \GraphQL\Error\Error(
        $e->getMessage(),
        extensions: array_merge(
            ['code' => $e->getErrorCode()],
            $e->getExtensions()
        )
    );
} catch (\InvalidArgumentException $e) {
    throw new \GraphQL\Error\Error(
        $e->getMessage(),
        extensions: ['code' => 'INVALID_ARGUMENT']
    );
} catch (\Throwable $e) {
    // In debug mode, the message is surfaced via DebugFlag
    throw new \GraphQL\Error\Error(
        'An unexpected error occurred.',
        previous: $e
    );
}
```

### 8.1. Staleness check

The build process includes a staleness check. This is invoked during the WooCommerce package build (`pnpm run build:zip`), NOT at runtime. It compares the modification times of all files in `src/Api/` against the `api_generation_date.txt` timestamp:

```php
// src/Internal/Api/Scripts/StalenessChecker.php

namespace Automattic\WooCommerce\Internal\Api\Scripts;

class StalenessChecker {
    /**
     * Returns true if the autogenerated code is stale (needs rebuilding).
     */
    public static function isStale(): bool {
        $timestamp_file = __DIR__ . '/../Autogenerated/api_generation_date.txt';

        if (!file_exists($timestamp_file)) {
            return true;
        }

        $generation_time = (int) file_get_contents($timestamp_file);
        $api_dir = __DIR__ . '/../../Api';

        $iterator = new \RecursiveIteratorIterator(
            new \RecursiveDirectoryIterator($api_dir, \FilesystemIterator::SKIP_DOTS)
        );

        foreach ($iterator as $file) {
            if ($file->getExtension() === 'php' && $file->getMTime() > $generation_time) {
                return true;
            }
        }

        return false;
    }
}
```

The `api_generation_date.txt` file contains a Unix timestamp:

```
1711468800
```

## 10. Default Field Resolver

Output type fields are resolved by `webonyx/graphql-php`'s default field resolver, which accesses public properties of the returned DTO objects. This means:

- Returning `$order->total_amount` just works — the library reads the public property.
- Enum properties (e.g., `OrderStatus::Pending`) are serialized by the generated `EnumType`'s value mapping.
- Custom scalar properties (e.g., a string property with `#[ScalarType(DateTime::class)]`) are serialized by the scalar's `serialize` callback.
- Nested object properties (e.g., `$order->customer` being a `Customer` DTO) are recursively resolved.

No custom field resolvers are needed on output types — the default resolver handles everything because the DTOs use public properties.

## 11. Type Mapping Reference

This section summarizes how PHP types in the Code API map to `webonyx/graphql-php` type expressions in the generated code. References use the new sub-namespace structure (e.g. `Enums\SomeEnum::get()`).

| PHP type | Nullable? | GraphQL type expression |
|---|---|---|
| `int` | No | `Type::nonNull(Type::int())` |
| `?int` | Yes | `Type::int()` |
| `float` | No | `Type::nonNull(Type::float())` |
| `?float` | Yes | `Type::float()` |
| `string` | No | `Type::nonNull(Type::string())` |
| `?string` | Yes | `Type::string()` |
| `bool` | No | `Type::nonNull(Type::boolean())` |
| `?bool` | Yes | `Type::boolean()` |
| `SomeEnum` | No | `Type::nonNull(Enums\SomeEnum::get())` |
| `?SomeEnum` | Yes | `Enums\SomeEnum::get()` |
| `SomeType` | No | `Type::nonNull(Output\SomeType::get())` |
| `?SomeType` | Yes | `Output\SomeType::get()` |
| `array` + `#[ArrayOf(X)]` | No | `Type::nonNull(Type::listOf(Type::nonNull(X_mapped)))` |
| `?array` + `#[ArrayOf(X)]` | Yes | `Type::listOf(Type::nonNull(X_mapped))` |
| `string` + `#[ScalarType(S)]` | No | `Type::nonNull(Scalars\S::get())` |
| `?string` + `#[ScalarType(S)]` | Yes | `Scalars\S::get()` |
| `Connection` + `#[ConnectionOf(T)]` | No | `Type::nonNull(Pagination\TConnection::get())` |

**Note on array items**: Items inside a `Type::listOf()` are always `Type::nonNull()` by default. This means `[AppliedCoupon!]!` in GraphQL terms — the list is non-null and each item in the list is non-null. This is the most common and safest pattern. If nullable items are needed in the future, an additional attribute (e.g., `#[NullableItems]`) could be added.
